# SenseHome 国一冲刺三人协作实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在不虚构真实设备、真实 6G 空口、客户或试点的前提下，把 SenseHome 从策略层工程原型提升为证据链完整的 AI+6G 场景设计候选项目。

**Architecture:** 以“网络—算力感知的家庭 AI 网关”为唯一主线。C 策略负责可解释路由，真实小模型负责自然语言动作规划，白名单负责安全执行，trace-driven 网络回放负责 6G 设计承载代理，PC 隔离状态负责可复现端到端演示。所有实测、仿真、设计目标和未验证事项分开标记。

**Tech Stack:** C99 策略核心、Python 标准库网关、AutoDL/vLLM 小模型、JSONL 评测集、TCP/trace-driven 回放、PC JSON 模拟设备、PowerShell、pytest/unittest、PDF/MP4 交付材料。

**Spec:** `research_official_rules.md`、`gap_judge_criteria.md`、`gap_technical_audit.md`。

## Global Constraints

- 赛道身份固定为“场景设计：面向实际需求的设计方案”。
- 不声称真实 6G 空口、物理设备、家庭试点或大模型推理已经完成。
- 正式评测默认使用 `eval_commands.reviewed.jsonl`；草案必须显式 `--allow-draft-labels`。
- 作品方案、PPT、视频和佐证材料必须匿名，不出现学校、单位、Logo、导师信息。
- 方案按更严格的 10 MB 控制；视频 3–5 分钟且不超过 300 MB。
- 每个数字必须能回到原始日志、JSON、脚本或公开来源。
- AutoDL 入口连续拒绝 2 小时或租用成本超过预算时，停止追连，保留已捕获证据并诚实标注。

## Review Focus

- 需求来源是否真实、授权是否清楚、现状基线是否可复核。
- 模型动作正确性是否与模型自报完成状态分离。
- 网络轨迹是否真的触发策略变化，是否把 TCP 台架误称为 6G 实测。
- 端到端时延是否包含探测、排队、模型、执行和回退。
- 作品方案、PPT、视频和佐证是否使用同一事实版本。

## 三人角色与接口

### 角色 A：系统与网关负责人

负责 C 策略、Python 网关、真实模型主路径、动作白名单、PC 隔离设备状态、故障回退和端到端测试。

产出：`gateway_e2e`、`compute_state`、端到端 JSONL、执行事件、回归测试、部署清单。

交给 B：每条请求的 route、reason、model_ms、network_ms、queue_ms、execution_ms、total_ms、fallback_reason。

### 角色 B：网络/6G/实验负责人

负责 trace-driven 网络回放、URLLC/eMBB/mMTC 业务画像、网络×算力消融、并发压力、p50/p95/p99 和结果复算。

产出：轨迹文件、轨迹生成/回放脚本、实验矩阵、原始结果、统计脚本、失败分类表。

交给 A：轨迹输入格式、网络状态字段、触发的策略变化；交给 C：所有可用于方案和答辩的最终数字及来源。

### 角色 C：需求/产品/材料负责人

负责真实需求访谈或问卷、KPI 字典、产业价值和成本模型、方案/PPT/视频/佐证材料、AIGC/许可/伦理/匿名审查和答辩。

产出：需求证据包、KPI 表、复制路径、BOM/成本表、最终 PDF/PPT/MP4、答辩问题卡、提交回执。

交给 A/B：需求约束、KPI 定义、材料中的唯一术语和数字口径。

### Task 2：需求真实性和 KPI 包

**Owner:** C。

验收：评委拿走需求方名称后仍能复述“什么业务、什么损失、改进什么指标、如何验收”。

### Task 3：真实模型端到端主路径

**Owner:** A；B 提供网络条件。

- [ ] 实现 `policy → wrapper → model → whitelist → isolated_state` 主路径。
- [ ] 统一事件 schema，禁止用 `semantic_complete` 代替参考动作判定。
- [ ] 将评测集扩展到 30–50 条，并保留至少 20 条独立 holdout。
- [ ] 在 AutoDL 可用时跑本地模型；不可用时保留现有 17/20 冻结后正式重新标注证据，不伪造新运行。

验收：每条请求都有原始命令、模型原始动作、归一化动作、白名单结果、执行状态和完整时延分解。

### Task 4：网络轨迹和 6G 设计承载代理

**Owner:** B；A 接入路由。

- [ ] 定义 URLCC、eMBB、mMTC 三类业务配置。
- [ ] 轨迹至少包含 RTT、抖动、吞吐、丢包、切换、边缘不可达。
- [ ] 统一 seed、版本和回放命令，保存原始轨迹和输出。
- [ ] 证明轨迹变化会触发 local-rules、local-model、cloud-model、自适应路径变化。

验收：任何人可用一条命令重放轨迹并得到同一策略变化；材料称“轨迹回放/设计代理”，不称“6G 空口实测”。

### Task 5：对照、消融和压力实验

**Owner:** B；A 提供埋点。

- [ ] 比较规则、本地模型、云模型、自适应四种路径。
- [ ] 做无任务分类、无双链路、无安全隔离三项消融。
- [ ] 覆盖 WAN 断开、LAN 未知、模型不可用、队列拥塞。
- [ ] 至少做 8 并发，条件允许时做 32 并发；报告 p50/p95/p99、错误和回退。

验收：不再使用不含探测时间的“快 4 倍”等倍率；所有比较使用同一任务集、同一轨迹、同一统计口径。

### Task 6：产业化、部署和复制材料

**Owner:** C；A 提供部署清单，B 提供网络资源假设。

- [ ] 形成网关、传感器、网络、模型服务和运维 BOM。

- [ ] 给出客户、付费方、运维方、数据责任方和失败回退责任。

验收：每个产业数字有来源或明确标记为设计目标；复制条件和重新配置项可执行。

### Task 7：最终材料和答辩

**Owner:** C；A/B 参加审稿。

- [ ] 方案按“需求—痛点—融合—架构—验证—价值—复制”重排。

## Go/No-Go 门槛

- **Go：**真实需求证据、端到端路径、网络轨迹、独立 holdout、全链路指标和材料一致性全部具备。
- **降级提交：**没有真实需求方时，以设计方案提交；没有真实 6G 时，以轨迹回放代理提交；没有物理设备时，以 PC 隔离设备提交。
- **No-Go：**任何人要求把模型桩、模拟设备、合成轨迹或预测市场数字写成真实结果时，停止该表述并保留诚实版本。
