# SenseHome 第二轮补证设计

承接用户“继续补齐”的执行授权，以本机、单人、无物理设备为固定约束。继续复用C/Python网关与现有权重，不改变已封存600条结果对应的源码、提示词或标签。

## 要补的实际能力

1. 从“覆盖健康观测”推进到实际HTTP故障/代理等待：自有代理真实返回503或施加固定700ms准入等待，底层模型正常运行。比较四臂能否识别不可用候选、避开代理排队，保留业务完成与失败。它仍是软件注入、同机GPU实验，不能作为实WAN/6G或真实GPU排队证据。
2. 让真实试用可以执行：独立localhost中文采集页，先知情同意，匿名记录实际任务与原话，允许取消，不采集身份信息；自测、自动化、练习和真实参与者分开，未收到人类提交前真实反馈维持0。
3. 从模型调用次数推进到实际usage账本：读取保存的上游响应token用量，逐调用可追溯；采购、整机能量、电价、维护无凭据则成本为null。增加实际支出证据账本与只读部署检查。

## 实验约束

- 两条已人工冻结的复杂任务×四臂×三重复×五条件，计划120行。固定设计后注册，再运行一次；不按结果增加注入强度或筛选成功命令。
- 五条件为双端健康、第二代理503、第一代理503、第二代理700ms等待、第一代理700ms等待。等待来自代理准入，不称GPU排队。
- 每条件独立初始化C历史，条件内连续重复；同一配对块同命令/初始状态/观测，四臂轮换；重复请求相关，不当作独立用户样本。
- 记录代理POST尝试与实际模型POST、原始响应、实际等待、候选健康、当前状态、失败、执行确认、时延和源码哈希。
- 原模型旧端口已退出时，可启动全新自有localhost进程并保存PID/资产哈希，不操作不相关进程。
