# SenseHome 第三轮竞争力补强设计

目标是按官方评分与公开获奖实例暴露实际差距，并完成本机可验收的关键改进。用户明确要求自行补齐，沿用自主执行授权，不重复审批。继续使用现有分支和Python/C工具，不创建会丢失未提交融合改动的新工作树。

## 要完成什么

1. 官方六维评分（20/10/30/20/10/10）、真实获奖案例、当前证据、优先缺口、整改验收逐项对齐。无同届国一历史或固定分数线时明确未知；不以类似比赛新闻推导本赛硬门槛。
2. 修复旧Dashboard网络请求失败后simulateLocal伪成功：错误/非2xx/畸形JSON只报未确认，不能伪造动作或传感器值；健康展示双端及未知项。只修改未列入封存12源码的页面/新测试，封存原始结果不变。
3. 新增独立、可选的纯规划故障恢复适配器。初选仍调用原C策略；仅复杂任务、可明确辨识的瞬态传输错误、未含动作/完成且替代端点就绪时至多调用一次另一规划端。4xx/非法输出/白名单拒绝/澄清终止。设备执行只在网关统一合同通过后发生一次。不重写旧网关，不利用H05调优。
4. 使用原冻结两条命令，预注册健康探测后POST503的竞态对照。原网关与恢复适配器同输入同状态，在本机真实模型上一次运行；保存启动argv/哈希、代理HTTP、原始计划、动作执行数。推理POST数量和失败不能省略。健康快照与实际故障相分离，不能用伪健康字段冒充当前测量。
5. 新增一键本机模型演示/doctor：显式配置本地已有模型文件、只回环、隔离状态、运行时manifest和退出清理；默认规则模式如实说明。无外部API/密钥/云连接。不继承旧模型端点。新开发与新矩阵独立v3目录。
6. 输出详尽差距报告、工程KPI验收表、单人实施/部署与回滚清单、20问证据稿、新ZIP。真实需求、物理设备、实网、实际总成本缺失继续标待验收。

## 验收重点

- 浏览断连零虚构成功；错误、无效状态不被计为完成。
- 恢复仅限规划，没有递归重试或先执行再重试。原/备端拒绝均不触发第三次推理。
- 相同command与context；primary/secondary分别记录，不能把恢复后的模型来源写成原首选。
- 旧ZIP与720行（旧600+v2新增120）哈希保护；无模型提示词/标签/旧C/Python变动。
- 新实验是软件代理与共享GPU，非6G/真实WAN或物理试点；公开案例不作性能基线。

## 已知外部缺口

实际外部使用者0；真实设备、两地网络、运营商平台、长期使用、客户KPI和成本凭据未取得。设计赛允许验证计划，不代表这些外部事实可用本机补造。
