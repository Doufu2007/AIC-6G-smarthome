# 部署清单与可复制路径

版本：2026-11-11。当前资源为一台现有 Windows PC，无新采购、无物理设备、无家庭试点；本轮不使用 AutoDL。下述“云候选”在本轮也部署于本机，它用于验证候选模型路径，不代表外部云或真实 WAN。

## 当前可复用部署角色和 BOM

| 角色 | 当前实现与数量 | 成本/资源证据 | 后续复制需补 |
|---|---|---|---|
| 设备端 | PC 隔离 JSON 模拟状态，1 份/运行；规则/动作白名单 | 不购买真实设备；可验证状态变化，非物理动作 | 灯具/窗帘/传感器型号、驱动、授权和联锁 |
| 家庭网关 | 同一 PC 的 Python 网关 + C 策略 CLI | 本机已有，无本轮采购账单；完整部署内存不可用 C 对象大小代替 | 独立主机选型、OS/工具链、存储与运维工时 |
| 本地小模型候选 | Qwen2.5-1.5B Q4_K_M，现有共享 llama.cpp 服务 | 权重 1,117,320,736 B；采样 RSS 中位 1,170,309,120 B | 固定版本/许可/上下文，目标硬件质量和性能 |
| 远端大模型候选代理 | Qwen3-4B Q4_K_M，也在同机；现有共享服务 | 权重 2,497,280,256 B；采样 RSS 中位 2,724,466,688 B | 若迁往独立节点，重新测传输/资源/费用；不能沿用本机成本 |
| GPU | NVIDIA RTX 4050 Laptop，单卡共享 | `nvidia-smi` 总显存 6,141 MiB，采样整卡已用 3,735 MiB | 不把 WMI 的截断 4GB 当容量；不把整卡已用全归因本系统 |
| 网络 | 既有 PC loopback/HTTP、软件条件 | 真实 HTTP 墙钟与显式注入/合成条件分别存储 | 独立 LAN/WAN 测量、接口和资费 |
| 语音入口 | 本轮以文本命令为准 | 未计麦克风、STT、TTS、唤醒词成本/准确率 | 需要语音时另加完整语音链和语言测试 |
| 运行维护 | 日志、源码/模型哈希、复现脚本 | 无真实维护工单或工时单 | 安装/升级/备份/恢复工时，数据留存和权限配置 |

本机资源原件：`docs/experiments/20261111_local_resources/baseline.json`；复算摘要：`host_resources_summary.json`。采样窗口为 2026-11-10 18:17:52—18:18:21 UTC（本地 11-11 02:17:52—02:18:21），30 个样本。主机 RAM 16,344,801,280 B，可用 RAM 为 906,969,088—1,104,297,984 B；这反映当时其他应用也占用的状态，不能据此宣布最低硬件要求或长期并发能力。GPU 功耗遥测只覆盖板卡且共享，不能代替整机电表。

## 无新采购的复现顺序

以下命令从仓库根目录运行，不需要云账号。不自动下载或重启已共享的模型服务。

1. 验证环境与源码：Python、C 编译器/已有构建脚本、模型文件及哈希。运行既有 `build.ps1` 后保留构建 manifest；不把旧可执行文件与新源码混用。

```powershell
powershell -ExecutionPolicy Bypass -File SenseHome-6G/net_offload/build.ps1
python -m pytest -q SenseHome-6G/net_offload/tests
python -m pytest -q openvela_smart_home/dashboard/tests
python -m pytest -q docs/deployment
```

2. 复用已启动的 OpenAI-compatible 小/大模型服务，在独立终端启动现有 wrapper。下列 `8000`/`18092` 是示例端口，先核对实际服务，避免端口冲突；模型 revision 必须填真实观察值。私密 key 仅注入当前进程，不保存入提交包。两份 wrapper 用不同端口、模型标识及 tier，不能让同一服务伪装成两个独立节点。

```powershell
$env:SENSEHOME_UPSTREAM_URL = 'http://127.0.0.1:8000/v1'
$env:SENSEHOME_MODEL = 'qwen2.5-1.5b-instruct'
$env:SENSEHOME_MODEL_REVISION = '填写本机实际版本或权重SHA256'
$env:SENSEHOME_TIER = 'gateway'
python SenseHome-6G/net_offload/backends/openai_backend.py --host 127.0.0.1 --port 18092
```

wrapper 合同为 `/health`、`/probe`、`/infer`，它不同于原始模型服务的 `/v1/chat/completions`。启动命令只表明配置了服务；必须通过健康与来源记录验证真实模型。

3. 运行现有隔离采证工具。它使用新输出目录，不控制真实设备，也不覆盖日常模拟状态；目录已存在时应换名称，保留旧证据。

```powershell
python docs/deployment/capture_real_gateway.py --url http://127.0.0.1:18092 --tier gateway --out _work/value_local_smoke_20261111 --repeat 1
```

采集后核对 `report.json`、`rows.jsonl`、原始 `backend_attempts`、事件、前后状态、源码 manifest 和失败。工具退出成功只说明其捕获流程/来源检查，不能替代冻结标签的语义准确率。完整配对评测以实验线的运行器及原始记录为准。

4. 如需演示 Dashboard，可使用现有 `bridge_server.py`，并显式设置 `SENSEHOME_LOCAL_URL`、`SENSEHOME_CLOUD_URL`、`SENSEHOME_POLICY_CLI` 和独立事件日志。现有 Dashboard 的默认状态文件与绑定地址见源码；在隔离演示环境中使用，正式设备接入前须增加身份/授权和隔离状态设置。不要把 Dashboard 默认模拟状态当作真实设备确认。

5. 资源和成本分开验收：采样 CPU/RSS/显存；墙上电表另测。用 `cost_current_unknown.json` 记录缺失成本，待取得实际电价、购置/分摊口径和集成电量后再填。没有完整账单也不阻止复现功能。

## 从一个原型到可复制交付

| 阶段 | 交付动作 | 可复核产物 | 继续条件 |
|---|---|---|---|
| 0：本机、模拟设备 | 重建策略、绑定现有模型、跑隔离状态与故障回退 | 版本/哈希、配置、原始输出、动作和资源记录 | 没有污染日常状态；来源与失败完整；当前可以执行 |
| 1：一个授权用户试用 | 按五分钟脚本，仅控制模拟灯和窗帘，采集原话与理解情况 | 匿名原始表、同意范围、事件引用、异常/退出记录 | 需要真实参与者；当前未执行 |
| 2：一套授权真实设备 | 集成商/设备所有者确认型号、动作、权限和恢复方式 | 驱动合同、状态确认、离线物理开关与联锁检查、真实工时/电量 | 需要硬件、授权及真实设备测试；当前未执行 |
| 3：集成商复制 | 将设备映射/模型地址/阈值作为配置，复跑同一验收集 | 每点配置版本、验收报告、维护手册、成本账目 | 至少一个真实点验证；当前无合作方或订单 |
| 4：跨场景推广 | 比较不同住宅网络、语言和模型；按适用范围发布 | 失败/成功分层、模型许可清单、版本升级和回滚记录 | 由实际样本决定范围；不提前写覆盖率/收入 |

商业模式目前只作为候选：系统集成服务、部署与维护服务、可替换模型接口。没有收费标准、意向客户或收入证据；公开云价不是对客户的售价。复制价值先用“他人能否按文档部署并定位一次故障”检验，再讨论规模化。
