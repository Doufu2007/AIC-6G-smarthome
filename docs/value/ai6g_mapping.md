# AI + 6G 技术映射与接口演进

版本：2026-11-11。映射依据为 ITU-R M.2160-0（2023-11，S6）及 ETSI MEC 官方说明（S7），不是标准一致性认证。现有 HTTP/TCP、软件轨迹和本机模型不属于真实 6G 空口。

M.2160 的 “Artificial Intelligence and Communication” 场景讨论跨设备与网络的重计算卸载、分布式推理和计算资源编排。SenseHome 的贴合点是“让网络状态与可用计算共同影响推理位置”。本作品只在请求级选择完整后端，没有实现模型层切分、跨节点训练、模型迁移或无线侧 AI 原生调度。

| 权威方向 | 当前可运行对象 | 当前证据边界 | 接入真实网络后需要的适配与验收 |
|---|---|---|---|
| AI 与通信协同、计算资源编排 [S6 §3] | C 策略读取两端健康、队列、并发、内存和网络指标，选择规则/本地模型/远端候选 | C 决策与模型请求可验证；两模型在同一 PC/GPU，远端位置是代理 | 两个独立部署点、版本可核验模型、实测传输/排队；保留同任务对照 |
| 泛在计算、工作负载放置 [S6 §2.2.2] | 对每个任务选择后端；支持未知观测与回退 | 是请求级调度，不是分布式神经网络计算 | 独立边缘发现、容量/许可协商、可用性监测；验证服务迁移和失败恢复 |
| 网络边缘信息供应用 [S7] | HTTP 探测 RTT、可达性；网络观测包含来源和观测年龄 | HTTP 往返包括应用/系统开销，不是空口时延；注入 loss/jitter 也不是无线实测 | 从获授权 MEC/运营商 API 获取可用字段；做单位、时戳、权限、TTL 映射与失效测试 |
| 可靠性、低时延 [S6 §4] | 业务时限、全部请求总时延、失败分类；WAN/LAN 两段分离 | 时限为应用配置；没有 URLLC/HRLLC 或确定性承载保证 | 校准单向/往返时钟、记录分位数与失败；使用真实链路重复实验，不把愿景指标当达标值 |
| 安全与韧性 [S6] | 白名单、参数检查、危险动作拒绝、失败回退 | 软件保护和模拟状态；不是设备功能安全或认证 | 用户身份/授权、传输保护、设备本地联锁、恢复验证和最小日志留存 |
| 可持续性 [S6 §2.2.9 / §4] | 模型调用数、CPU/RSS/显存观测；成本公式可复算 | 调用减少不等于能耗减少；GPU board power 非整机能耗 | 插座电表积分电量、同负载同质量成对测量；核算常驻和冷启动，不提前声称节能 |
| 互操作与边缘开放接口 [S7] | OpenAI-compatible wrapper、JSON 动作合同、C CLI | 是本项目 API 适配，不是已通过 MEC 一致性测试 | 真实平台的鉴权、发现、服务 API 版本与错误模型；保存合同测试和兼容清单 |

## 建议保留的技术接口

1. 网络适配层保留 `value/unit/source/observed_at/age/known` 语义；缺字段保持未知，不把“无数据”填为零时延或零丢包。WAN 与 LAN 各自有可达性和测量来源。
2. 模型适配层保留模型标识、权重哈希/部署版本、可用性、并发/队列和资源观测；不能由模型自报字符串单独证明权重身份。
3. 路由层继续调用唯一 C 实现；平台字段通过 Python 映射，不在适配层复制决策表。真实 API 版本和未知字段的行为应有合同测试。
4. 记录层保留来源：本机实测、外部实测、软件注入、合成轨迹、模型推理或规划桩。统计只合并同证据类型；模型输出与动作结果分别记。

## 演进顺序与退出条件

| 阶段 | 可做工作 | 进入下一阶段需要的事实 |
|---|---|---|
| 当前本机设计验证 | 共享 GPU 两模型、C/Python 网关、模拟设备、明确的软件链路条件 | 配对模型输出、失败、动作与资源证据；不要求租云 |
| 独立家庭/边缘节点验证 | 用户授权后将候选模型放到独立主机；实测 LAN/WAN | 硬件清单、真实吞吐/RTT、资源与电量、部署工时；这一步也不等同于 6G |
| 授权运营商/MEC 接口试验 | 接入平台可用观测；记录标准版本和鉴权 | 平台权限、试验计划、真实接口记录和网络说明 |
| 未来 6G 试验环境 | 以实际试验网能力验证应用适配收益 | 可核实的试验网/空口与设备记录；没有这些就继续写设计映射 |

家庭网关通过 Wi-Fi/以太网与未来移动网络协作是可能部署路线，但不是本作品已实现的 6G 接入。在现阶段，6G 的作用是给出网络与计算协同的目标和接口方向；本地 PC 复现实验回答应用策略能否工作。
