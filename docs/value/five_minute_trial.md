# 五分钟模拟设备试用与需求采集表

版本：2026-11-11。状态：**尚未执行；有效受访/试用人数 0**。本页是可立即使用的采集工具，不是访谈结果。开发者自测须记为 `developer_self_test`，不得合并为用户研究；不能由 AI 代填回答。

## 开始前准备（不计入五分钟）

- 仅连接 PC 隔离的灯/窗帘模拟状态，关闭主动巡检；不连接门锁、燃气或真实家电。确认模型/规则来源及网络条件可见，备份并记录初始状态。
- 若可手动切换演示网络条件，必须显示“软件注入 WAN 不可达，LAN 模拟可用”；没有该控制入口则跳过 T3 并记 `not_run`，不真正断开家中网络。
- 每个会话生成匿名编号，例如 `T001`；记录版本、模型、条件、开始时间和事件文件相对路径。原始自由回答单独脱敏保存，不记录姓名、住址、账号或家庭真实配置。
- 使用者自愿同意后才开始；默认不录音/录像，仅记录脱敏文字。若不愿公开原话，只保留其明确允许的摘要；不同意或中途退出均计入招募流程记录，不计有效完成。

开场白：“这是一个家庭控制入口原型，今天只操作电脑里的模拟灯和窗帘。模型可能失败；请按自己的理解操作并说明看到的结果。你可以随时停止。是否同意我记录匿名操作结果和你允许记录的回答？”

## 五分钟脚本

| 时间 | 操作/提问 | 记录什么 | 不引导的判定 |
|---|---|---|---|
| 0:00–0:40 | 询问“你平时用过哪些家庭控制方式？最近有没有一次不顺利的情况？想不起来也可以。” | 使用方式、是否有实际经历、原话/无经历 | 没有经历就记“无/想不起来”，不补故事 |
| 0:40–1:20 T1 | 显示设备清单后，请输入“打开客厅的灯” | 原始命令、路由、动作、最终模拟状态、请求总时延 | 预先标注灯由 off→on；HTTP 200 或模型说“完成”不算状态确认 |
| 1:20–2:10 T2 | 请输入“把客厅灯光设为60%，再把卧室灯光设为30%” | 两个动作是否都正确、失败/回退、用户是否需要帮助 | 以冻结参考动作和模拟状态分别判定；原始错误必须保留 |
| 2:10–3:10 T3 | 操作者切到明确标注的软件 WAN 故障条件；请再执行一次 T2，并问“你认为现在还可以做什么？哪些功能受影响？” | 实际条件、后端、失败/降级提示、未提示前的复述原话 | 记录其真实理解，不先教答案；未运行就记 not_run |
| 3:10–3:40 T4 | 请输入“把阳台灯打开”（清单中无阳台设备） | 是否拒绝/澄清、是否有任何非预期动作、前后状态 | 预期无设备状态变化；不以用户满意代替动作校验 |
| 3:40–5:00 | 问下列四个简短问题，允许“不知道” | 原始回答、操作帮助、退出/超时原因 | 不把“愿意再试”写成愿意付费 |

四个结束问题：

1. “刚才最清楚或最困惑的一处是什么？”
2. “如果这是你家，你希望故障时界面告诉你什么？”
3. “这类控制中，你愿意接受哪些命令进入外部模型，哪些希望只留本地？为什么？”
4. “你是否愿意在有明确设备清单和数据范围的条件下再试一次？愿意/不愿意/不确定及原因。”

不在这轮短试用中问假设性购买金额。若后续专门研究预算，应先明确实际部署包、替代品、维护责任和对方决策权，保留“不了解/不负责采购”，不能把估计金额当付费承诺。

## 汇总规则（取得真实记录后再计算）

- 分别报告邀请、同意、完成、退出、技术条件不可用的人数；不得只统计成功完成者。
- 功能任务：正确动作率、状态确认率按各任务实际运行数分别计算；失败和超时进入分母；`not_run` 单列。声明设备始终是模拟。
- 可理解性：由预先定义的两个要点核对复述（识别当前故障影响的路径；知道剩余能力/下一步），保留原话，并在多人时由另一人复核。没有回答即缺失，不能判通过。
- 延时仅使用日志的全部请求 `total_user_ms`/对应墙钟口径，不与模型时延混用。样本小先逐条展示，不推断人群比例或市场规模。
- 任何满意、偏好或再次试用回答均只覆盖该会话；不能上升为实际部署效果、采购意愿或商业验证。
