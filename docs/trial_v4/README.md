# 真实需求与完整模型试用入口

本轮已有人愿意参与（用户自报），尚未取得具体原话或操作记录，外部反馈计数仍为0。工具不替人回答，不联系他人，不生成满意度数据。

## 正式试用

模型评测结束后，在项目根目录打开终端：

```powershell
python -X utf8 docs/trial_v4/run_trial.py --record-kind participant
```

打开 http://127.0.0.1:8877 。此入口**默认启动完整的两个本机模型**、隔离网关、真实本机MQTT服务及持久软件实体，可能需要等待启动。模型文件校验、端口或启动失败即报错退出，不能悄悄切到规则版。两个模型共用这台电脑和GPU，设备为软件模拟。请勿和模型评测同时运行。每次启动只接待一人，下一位需重启服务。

开发者检查用 `--record-kind developer_self_test`（默认）；自动检查用 `--record-kind automation_test`。资源不足时可明确加 `--rules-only` 进行工具练习，页面会标出能力范围，不能据此评价完整模型能力。

每位参与者顺序：

1. 自愿阅读范围、同意保存；匿名原话公开引用默认关闭。
2. **操作前**自行记录原有控制方式、具体经历、影响、希望改善什么、可接受等待时间。不知道、没有困扰、不需要改变、跳过都有效。此记录在开始任务后冻结。
3. 优先自行提出任务。预设练习单独标记，不能说成自主需求；自拟任务没有人工冻结参考答案，自动正确性为null。
4. 保存失败、困惑和不愿再用的原因。完成/部分完成/未知需让对方按自己的理解复述，不替对方纠正原话。
5. 任务命令、模型响应、软件状态、MQTT回执会立即写入本次私有运行目录，开始前需向参与者说明。需求回答和反馈最后自行点击“确认保存匿名记录”才保存。取消/撤回会先正常关闭本次服务，再删除本次v3/v4私有目录和该反馈记录；未保存就Ctrl+C也删除。终端必须出现 `private_run_cleanup.all_absent=true` 才确认清理完成，失败时人工处理本次精确目录。普通文件删除不保证覆盖磁盘历史数据。

已经明确保存后Ctrl+C会保留反馈及其关联运行证据，供已授权的分析；之后撤回需操作者同时删除该反馈和provenance指向的两处私有运行目录，不要只删反馈文件。未保存或取消不能自动变成匿名可引用资料。

数据在 `docs/trial_v4/data/`，默认不进Git或审阅包。匿名记录本身不证明操作者身份，文书同学还需核对实际招募过程；便利样本不支持市场普遍认可。引用必须检查每条 `allow_anonymous_quote`，未授权原话不放公开材料。

## 文书同学组织表

| 项目 | 记录方式 |
|---|---|
| 招募来源 | 同学/亲友/实际集成人员等，不记录不必要的姓名地址；说明便利样本 |
| 是否实际使用智能家居 | 依据原话，未使用者也可参加但分开描述 |
| 现有流程和具体困扰 | 保留原话；没有困扰同样记录 |
| 自拟任务与反馈 | 以工具保存的任务、状态、网关响应和时间关联 |
| 引用授权 | 单独核对，默认无授权 |
| 验收目标 | 只能把参与者实际表达的目标写为来源；工程建议单列 |

不要在未采集前填满3—5份表，也不要把该人数写成官方门槛。请先交付真实的一位，再继续收集。

## 验证

`python -X utf8 -m pytest docs/trial_v4/test_trial.py docs/trial_v2/test_collector.py -q`

测试覆盖需求先于任务、允许无困扰/拒绝使用、任务后不可改操作前回答、单次只接一人、中文完整、默认模型模式及长度限制。`test_private_cleanup.py` 使用真实子进程、网关及MQTT验证：执行一条命令后取消，正常退出且两处运行目录和反馈均不存在。完整模型HTTP自测见 `full_model_smoke.json`；它不计外部用户。
