# Dashboard v3：可核验的网关演示

修改日期：2026-11-11。

修复对象为 `openvela_smart_home/dashboard/web_panel.html`。本项未修改封存的生产 Python/C 文件，也没有改写旧的600行、v2新增120行实验结果和旧交付包。

## 已修复的可见行为

1. 删除断连时按关键词拼接成功动作和传感器数值的 `simulateLocal`。网络、HTTP非成功状态、JSON解析和响应契约错误均显示“执行未确认”，不自动生成动作。
2. 仅当网关返回布尔型 `semantic_complete=true`、`interface_ok=true` 和合法动作列表时，显示“网关报告完成（PC仿真）”。需澄清、拒绝、业务失败均明确标为未完成。
3. 请求响应丢失不等于服务端未执行；页面提示先查询设备状态后再操作，避免诱导重复下发。
4. 设备状态读取校验六个位置的灯光、窗帘和温湿度核心字段。失败时清空当前确认状态、显示未知并禁用状态不明的灯光控件；缺少传感器字段显示未知，不补0、无人、门关或25°C。
5. 命令、网关返回文本、动作说明、巡检文本、安防模式都按文本转义，避免作为HTML执行。
6. 健康栏同时展示两个模型端点的ready/reachable、缓存年龄、队列和可用显存。未观测的资源保持未知；包装器“无等待队列”不冒充上游模型队列为0。显示链路测量来源。
7. 首页明确标示PC设备仿真范围，去掉初始化时“已就绪”“DeepSeek”“QEMU已连接”等未经响应确认的表述。

## 自动验证

```powershell
node --test docs/demo_v3/dashboard/test_dashboard.cjs
python -m unittest discover -s openvela_smart_home/dashboard/tests -p 'test_*.py' -v
```

实际结果：首轮页面JavaScript行为测试9/9通过；Dashboard既有Python测试45/45通过。浏览验收后增加3项完成文案与规划来源测试，目前页面行为测试12/12通过。

- `red-test-output.txt`：修改实现前，9项行为测试全部因现有缺陷失败的实际输出。
- `green-test-output.txt`：实现修复后，9项行为测试通过的实际输出。
- `python-regression-output.txt`：45项既有Python测试通过的实际输出。
- `test_dashboard.cjs`：Node内置测试运行器，提取并执行真实页面脚本，仅将外部fetch和DOM边界替换为受控输入。
- `provenance_red.txt`、`provenance_green.txt`：后续3项呈现缺陷先失败、修复后12项全部通过的实际输出。完成块使用网关事实短句，原answer独立标注为执行前接口答复；恢复用例显示C初选、真实备端来源及首端HTTP错误。

12项测试覆盖：fetch拒绝、HTTP503伪成功body、坏JSON、业务未完成、结构化成功与HTML注入转义、HTTP200坏schema、状态读取失败及坏schema、缺失传感器、双模型健康及未知遥测、规划器答复与执行完成区分、首端失败/备端规划成功的完整来源及错误、缺少actual_backend时使用实际source。

这些是自动化边界测试，不是人工核对、真实用户试用、真实硬件测试、真实6G链路测试或完整浏览器验证。页面展示的完成状态来自网关报告，设备仍为PC仿真。

## 浏览器交接验收

由主代理在已运行的网关上打开页面验证：正常灯光动作显示网关报告完成；“有点暗”等缺目标表达显示未完成并保留澄清；停止网关后发送“太暗了”只显示未确认，所有房间恢复未知；健康栏同时出现local-model/cloud-model与未知遥测。此处仅提供验收步骤，不预先声明验收通过。

## 仍需通过其他任务解决

本修复保证前端不自行伪造成功，但不替代模型能力评估、真实场景访谈、外部用户试用和实物/真实链路验证。真实模型效果与国赛获奖可能性应引用独立实验和评审证据。
