# 项目技术修复版（2026-11-12）

本目录对应 `docs/reviews/2026-11-12-intrinsic-project-audit.md` 的 F01—F11。运行入口继续复用当前源码的 `docs/demo_v4/live_v4.py`；原 v1—v4 封版实验保留为历史证据，不能作为本次新版本的模型成绩。

## 启动

从项目根目录启动规则与 MQTT 软件实体，使用固定数据目录以支持整体退出后的恢复：

```powershell
python -X utf8 docs/demo_v4/live_v4.py --rules-only --data-dir "_work/deployment/home"
```

用启动输出中的本机地址打开页面。默认端口为 8879；可以用 `--port 0` 分配空闲端口。完整本机模型模式去掉 `--rules-only`，运行时和模型配置位于 `docs/demo_v3/local_models.json`，启动前会校验已有文件的哈希，不会下载模型。

```powershell
python -X utf8 docs/demo_v4/live_v4.py --strategy local-first --data-dir "_work/deployment/home"
```

`--strategy joint` 启用联合初选，使用真实适配器排队/在途观测和有足够新鲜样本的分任务代价；没有观测的 GPU 排队、显存和带宽继续为未知。默认策略仍沿用历史小规模实验的临时选择，不宣称 joint 已超过简单策略。两个候选模型在同一台电脑上，不是独立边云设施。

## 可直接检查的行为

- “把客厅灯光设为60%，再把卧室灯光设为30%”：须完整覆盖两房间、数值和顺序。错计划在执行前拒绝；回执和足够新的当前软件状态共同支持任务验收。
- 模型只接收服务器解析后的完整指令，ID及调度遥测留在外层。完整支持请求被误回空计划时，可在剩余预算内尝试一次备用模型；原始输出及备用原因保留，不能把接口成功当作任务成功。
- “有点暗”→“卧室”→“调到60%”：在同一页面会话续接。可说“取消”；待澄清意图五分钟后过期。不会猜“亮一点”对应的百分比。
- 每次请求先保存 ID 并在规划前登记。响应丢失后点“回查上次请求”；刷新仍保留 ID。若要结束等待，点“结束等待并保留记录”；旧请求仍可能执行，可在历史记录里继续回查。该动作不会撤回或重发旧命令。
- 模型正在处理时仍可查询健康和缓存状态。HTTP 工作线程和命令准入均有限额；正式入口有 10 秒提交期限，首端规划预算上限 4 秒。已提交动作超时后只查原 ID。
- MQTT 断开后可重连并重新订阅；旧命令不因重连重发。页面显示最后采样时间、数据年龄和过期/未知状态。
- 离家模式实际支持五房间灯帘，共十个动作；安防布防未接入，因此整体 `task_complete=false`，同时报告支持范围是否完成。
- 巡检通过统一命令、白名单与回执通道读取五房间温湿度；缺少可信光照/人体数据时不编造自动控制。

持久目录的文件、锁、启动对账和备份方法见 [部署说明](persistent_deployment.md)。同目录仅允许一个应用实例；未知数据版本拒绝自动接管。重启恢复从账本和当前实体观测验收，不自动补发未知命令。旧版本中断记录若没有足够的完整目标，只能继续报告未确认。

## 验证

```powershell
python -X utf8 docs/intrinsic_v5/run_checks.py
node --test docs/intrinsic_v5/test_dashboard_requests.cjs
```

Python 入口将原设备状态和事件文件隔离，保存命令、日志及前后哈希。活动源码与故意导入冻结源码的历史兼容测试分别运行于独立进程，避免同名模块污染。仓库根目录裸跑 pytest 会收集旧源快照的同名模块，不是此入口的活动测试范围。

这些修复覆盖软件工程行为。MQTT 回执和软件状态均不等于物理灯具动作确认；真实模型烟测也不能替代大规模准确率、真实 GPU 队列或实际 6G 链路实验。
