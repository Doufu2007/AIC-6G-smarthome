# 在线资源与代价更新

对应 F11。此次补齐正式运行链路可测部分，不把未知 GPU 队列或无线带宽补成零。

`DirectModelBackend` 在进入单槽推理准入前登记等待，获得准入后登记在途，结束或放弃时释放计数。每次推理使用独立 `RecordingService`，健康请求使用另一实例，避免并发污染模型原始交换记录。日志列表有上限并受锁保护。

`OnlineMetrics` 提供 `waiting_requests`、`inflight`、最近实际准入等待时间，以及标记为 `adapter_serial_admission` 的排队估计。排队估计由当前在途任务的预计剩余时间和等待数量计算，仍是估计值；它不声称测到了上游 GPU 的服务队列。`upstream_queue_ms` 与 `free_mem_mb` 保留 null。

成功完成的规划按读/控制、单目标/多目标分组，记录准入后的实际 HTTP/规划 wall time，采用 EWMA 更新。至少两个样本且年龄不超过30秒才可用；不足或过期回到配置先验。失败不作为成功任务代价样本；本轮没有声称这能预测任意新任务的耗时。

健康快照接入这些实时计数；命令按任务类别选取新鲜代价，送入 `ResourcePolicyClient`。该代价已包含传输，不再叠加 C 策略中的同一 RTT/传输成本。未知带宽继续影响可推导范围，不能根据 loopback 结果虚构真实6G链路。

HTTP 记录拆分请求连接/发送、响应头、响应体的客户端观测耗时；字段明确标注它们不等于独立 GPU 推理耗时或无线传输耗时。绝对 deadline watchdog 同时约束慢滴响应头和读响应体阶段。

验证分两层：

- `test_online_metrics.py` 检查实际计数/分任务更新/30秒过期/未知字段；以同一受控观测改变新鲜任务代价，验证实际 C 初选从第二模型变为本地模型。
- `test_integrated_service.py` 启动真实本机 HTTP、正式适配器和受控规划响应；并发请求真实形成一个在途和一个等待，健康仍可访问，释放后形成两个成功代价样本。它验证服务排队和接线，规划响应是测试夹具，不能称为真实模型质量结果。

新版本真实模型烟测另存于 `real_smoke_report.md`。本轮没有重新运行公平三策略大矩阵，也没有证据将 joint 宣称为最优默认。默认仍保留简单策略，联合策略用于已观测资源/任务代价条件下的可检查初选。
