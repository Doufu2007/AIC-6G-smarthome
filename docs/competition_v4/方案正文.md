# 场景设计方案

## 6G链路自适应家庭AI推理系统

SenseHome  2026年11月11日  v4

场景类型  面向实际需求的应用场景设计方案

## 作品简介

家庭自然语言控制依赖模型和服务可用性，收到接口响应仍可能没有完成指令。SenseHome面向存量住宅集成服务，提供设备规则、网关模型与第二模型候选，由统一网关完成任务分类、初选、最多一次规划恢复、动作白名单及状态核验。同机双模型上比较本地优先、第二端优先与联合初选，三臂共用恢复规则、模型、提示、超时和初态。六类条件下复杂任务各完成20/24，预设规则推荐本地优先，未证明联合具有完成率优势。正式执行通道接入持久命令身份、冲突检查、回执和状态回查，实际MQTT软件实体六类故障核验通过，未知结果只回查，不盲目重发。软件状态、真实模型、代理故障和历史合成结果分层保存，原250毫秒目标未达记录完整保留。当前为设计验证阶段，两个模型共享本机GPU，MQTT实体和JSON状态不代表实物完成，尚无真实6G空口、独立主机及外部用户反馈。后续以授权试用、低风险设备、独立网络和实际成本逐层验收。

主线  家庭复杂指令在后端异常时的恢复与执行核验。当前成熟度为软件原型与分层验证。

# 一 场景概述与需求来源

## 目标角色与业务流程

设计面向为存量住宅接入灯光、窗帘和环境设备的集成服务者，最终使用者为住户。使用者发出自然语言指令，集成服务者负责配置权限、定位异常与维护系统。该客户画像仍是设计定位；真实反馈保存前，项目外部反馈数保持0。

## 需要解决的问题

网络可连接时，模型调用仍可能超时或返回不合规动作。自动重试又可能重复控制设备。操作者需要区分请求收到、计划生成、已提交与状态确认，并知道哪一部分没有完成。

| 当前环节 | 失败后果 | 方案响应 |

| --- | --- | --- |

| 自然语言交给单个模型 | 服务异常后复杂指令中断 | 受约束的一次备用规划 |

| 模型计划直接作为成功 | 越权动作或空计划被误报 | 整项动作校验和状态核验 |

| 执行超时后再次发送 | 同一动作可能重复 | 持久命令身份与回查 |

## 需求证据状态

公开平台文档用于解释技术背景，不能代替本项目住户访谈。中性提纲与完整模型版隔离试用入口已准备；尚未保存的授权、原话、用户任务与等待阈值均保持待采集。

# 三 系统架构与业务流程

![图1 当前软件角色与接口结构](_work/submission_20261111_v4/architecture.png)

## 一次请求

明确支持的简单命令与只读查询使用规则。复杂指令先读取带来源和年龄的观测，再选择首个候选。合格传输失败最多发起一次备用规划；两个候选均失败时报告未完成。模型只产出计划，统一网关在白名单校验后执行。

执行提交前持久化命令与动作。回执应绑定动作、command_id及平台身份；确认丢失时查询状态，同ID异payload视为冲突。无法确认时保留unknown，并向操作者报告。

图1的规则、模型、执行路径均由网关统一记录。所有“第二端”均指逻辑角色，当前不称云端独立节点；部署清单为Python网关、C策略、llama.cpp、两个GGUF、SQLite及MQTT服务与客户端。

# 三 关键机制与已有方案差异

## 初选与恢复分开验收

初选决定先调用哪一候选，恢复器决定合格失败后是否尝试备用。三臂共享恢复器，避免把恢复能力只给联合策略。本地优先是合理的强基线；若它在本轮更好，就采用它作为默认，C联合策略保留为未来真实资源观测的扩展。

## 执行核验

动作合同约束房间、设备与允许值，越权或畸形计划整项拒绝。持久命令与状态回查补上跨请求、ACK丢失和重启后的对账；逐项状态支持部分完成，不承诺多设备物理原子回滚。

| 对标 | 已有能力 | 本作品验收重点 |

| --- | --- | --- |

| Home Assistant Assist | 本地自然语言与模型接入 | 异常后的来源与逐项执行状态 |

| Home Assistant AI agent | 本地意图优先和实体授权 | 三臂同款恢复比较与事件证据 |

| RouteLLM | 成本质量驱动模型路由 | 家庭动作合同及网络算力观测适配 |

不将规则优先、动作白名单或模型路由单独宣称首创。尚未开展竞品同硬件同任务性能对照；差异是具体工程组合与可复核验证范围。

# 四 持久回执与MQTT软件实体

正式网关已接入持久回执适配器。实际本机MQTT服务、客户端与SQLite软件实体完成六类故障核验，均PASS；逐项记录见佐证。

| 情形 | 合同要求 | 可验收观察 |

| --- | --- | --- |

| 重复命令 | 相同ID相同payload只复用记录 | 不新增动作提交 |

| 同ID异payload | 拒绝冲突 | 冲突记录且状态不变 |

| ACK丢失 | 结果未知后只查询 | 不因超时盲目重发 |

| 网关重启 | 从持久库恢复待确认记录 | 回查并保留原命令身份 |

| 部分或矛盾回执 | 逐项报告；不接受不一致身份或动作 | 已确认、未执行、未知分别保存 |

MQTT使用实际AMQTT 0.12.1、paho 2.2.0、协议消息与软件实体。正常控制与回查走正式网关；部分完成的二动作场景使用固定contract probe，不称真实模型推理。软件实体状态不证明实物灯具或执行器动作。

数据库与事件记录用于回放和核对。当前不承诺物理exactly-once、断电后硬件位置可靠、生产鉴权或安全认证；这些须在授权低风险设备上独立验收。

# 四 部署复制与稳定性

本轮从新目录复制57个源码文件，自动启动至就绪3013.4ms，首任务95.4ms。规则路径以1请求/秒运行约120秒，共120请求，120条行为符合预期、传输错误0。

## 复制路径

复制到新目录，核验运行时、DLL、模型和策略哈希，实际绑定端口后再启动。默认规则版与完整模型版隔离状态；模型版采集器应记录同意、用户自拟任务、实际结果与反馈。回滚只停止本轮拥有的进程，保留记录，再切回已验收规则路径。

| 验收项 | 本轮可自动完成 | 需要真实外部输入 |

| --- | --- | --- |

| 新目录启动 | 哈希、启动、首个任务和错误定位日志 | 同学独立操作及真实人工工时 |

| 固定负载 | 固定请求率、故障序列、资源和事件计数 | 长期真实家庭负载 |

| 成本 | 分项账本与未知传播 | 采购、整机能耗积分、电价和维护工时 |

| 迁移 | 协议与接口合同 | 独立主机、实网、授权设备 |

固定负载仅为规则路径加MQTT软件实体，未做模型浸泡测试。自动部署耗时是自动化墙钟，不称同学人工安装工时。两分钟负载不等于长期生产稳定；独立主机与真人独立部署仍待实测。

# 五 产业价值与推广路径

## 先验收可量化的服务价值

目标价值是减少受支持任务在模型异常时的中断，并让维护者查清失败环节。采用同任务比较完整完成数、全请求等待、人工重试、调用开销和部署维护工时，避免用接口200或演示流畅度代替业务效果。当前尚无客户采用、收入或市场规模实证。

| 阶段 | 验收内容 | 退出或扩展条件 |

| --- | --- | --- |

| 授权探索 | 3—5位自愿者先谈现有方式、具体困扰与影响 | 没有痛点也照实保存 |

| 任务试用 | 参与者自拟任务、实际过程、反向反馈及等待阈值 | 开发者和自动化不计外部用户 |

| 低风险试点 | 一类灯光设备、独立网络、回执和回滚 | 只扩展已验收权限 |

| 复制推广 | 独立操作、实际成本、维护负担 | 有净价值证据后再谈规模 |

月成本可按硬件摊销、电费、推理、网络与维护分项，单位成功请求成本以成功数作分母。当前采购、电价、整机能耗及工时缺凭据，总成本为null；本机无外部API收费不等于系统零成本。
