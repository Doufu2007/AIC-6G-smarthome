# 真实模型开通后的本地闭环采证

`capture_real_gateway.py` 从本机通过真实HTTP访问SenseHome wrapper，依次调用当前 `policy_cli.exe` 的C策略、`bridge.process_command`、白名单动作执行器，并把动作写入独立临时PC JSON状态。不会操作日常 `openvela_smart_home/device_state.json`，也不会控制物理设备。

前提是本机已有构建好的策略CLI，且wrapper通过本机回环端口可达。`--url` 要指向提供 `/health`、`/probe`、`/infer` 的wrapper，不能直接填vLLM的 `/v1` 接口。不把凭据放入URL；脚本会拒绝含用户信息、query或fragment的URL。

## 执行

从项目根目录执行；端口按本机实际转发替换，输出目录必须是全新路径。

```powershell
python docs/deployment/capture_real_gateway.py --url http://127.0.0.1:18092 --tier gateway --out _work/real_gateway_small_20261103 --repeat 1
```

大模型对应cloud档的可控路由输入：

```powershell
python docs/deployment/capture_real_gateway.py --url http://127.0.0.1:18093 --tier cloud --inject-lan-ok --out _work/real_gateway_large_20261103 --repeat 1
```

每轮真实执行六条命令：开灯、只读安防查询、“客厅有点暗”、灯光加窗帘复合指令、越权门锁请求、否定指令。不会预写成功动作或期望结果；安全拒绝、空动作、模型未理解、回退及异常均保留原始结果。

## 网络输入的含义

- gateway档：WAN不可用是显式注入的路由条件，LAN可达性和RTT来自本机到wrapper的实际 `/probe` HTTP往返。
- cloud档：WAN可达性和RTT来自实际 `/probe` HTTP往返。LAN默认未知，在证据中保留null；C的布尔协议把未知保守编码为不可用，因此complex任务会出现 `LAN_DOWN` 并走本地规则。
- cloud档显式传 `--inject-lan-ok` 时，LAN可用标记为 `injected_route_fixture`，LAN RTT仍未知。该选项只提供可控路由输入，决策仍由现有C策略执行。

以上不是家庭WAN/LAN时延、实际断网、移动网络或6G空口的实测；SSH转发会成为HTTP往返路径的一部分。只读安防和简单开灯仍按现有策略走本地规则，不因为远端开通而改成模型执行。

## 输出与判读

输出包含 `report.json`、逐条追加的 `rows.jsonl` 和 `events.jsonl`、`health.json`、各次实测 `probe.json`、`initial_state.json`、`final_state.json`、`source_manifest.json`。每行保存完整前后状态、完整gateway事件以及模型原始 `backend_attempts`。后者保存网关安全拒绝或回退之前的HTTP动作，避免只看到回退结果而丢失失败原因。

`source_class` 分为 `rules`、`real-model`、`fallback`、`unverified-upstream` 和采集异常。`real-model`依据wrapper实际报告的来源，模型ID、revision和GPU声明应再与独立的模型部署日志/权重哈希核对，不能只凭字符串证明权重身份。

脚本记录源码与策略CLI的SHA256，并核对正常状态文件字节未改变。新目录规则防止覆盖旧证据。健康/探测失败、接口错误、回退、未验证来源、没有观测到真实模型路径等情况将保存JSON后返回非零；会尽量完成其余命令，不能删除失败行后只展示成功行。

退出0只表示本次捕获流程和来源检查通过。本脚本本身不计算语义准确率；正式准确率应使用已冻结的 `SenseHome-6G/net_offload/backends/eval_commands.reviewed.jsonl` 与 `eval_model.py`，也不会把 `semantic_complete` 声明当作人工判定的正确性。当前结果只对应PC模拟设备和注入的路由输入。

## 本地验证

```powershell
python -m unittest discover -s docs/deployment -p test_capture_real_gateway.py -v
```

测试运行真实策略CLI、真实Dashboard状态执行和本机HTTP假上游，覆盖gateway、cloud未知LAN/显式注入、安全动作拒绝后的原始动作留存、状态隔离及禁止覆盖目录。假上游测试仅验证采证工具，不能当作真实模型结果。
