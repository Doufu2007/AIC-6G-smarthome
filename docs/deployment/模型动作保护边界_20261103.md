# 模型动作保护修复记录（2026-11-03）

## 触发与根因

真实小模型的草案预检出现了“把灯调亮一点”被规划成客厅动作的情况；另一次预热中，模型在尚未执行时回答“已经打开了客厅的灯”。动作白名单只能确认动作名称、位置枚举和参数是否合法，不能证明该位置由用户选定，也不能验证模型回答的执行事实。

本次修复位于 `SenseHome-6G/net_offload/backends/openai_backend.py`，没有修改 C 路由、设备执行器或标签草案。旧远端运行仍属于修复前证据，不得回填为新实现的成绩。

## 当前保护

- 每个规划动作的位置必须在原始 `command` 中显式出现。当前协议没有可信的隐含房间上下文，因此 `context.location` 不能代替显式位置。任何额外位置使整批动作以 HTTP 422、`MODEL_ACTION_TARGET_UNMENTIONED` 和空动作拒绝。
- 对已识别的中文否定或条件表达，含灯光或窗帘变更的整批计划以 HTTP 422、`MODEL_ACTION_REQUIRES_CLARIFICATION` 和空动作拒绝。只读温湿度查询和空计划继续有效。
- 非空计划返回固定提示“动作计划已生成，等待网关执行确认。”，不传播模型自由文本的提前成功宣称。`semantic_complete=false` 保持，实际执行和确认仍由网关负责。
- 结构错误仍使用 `INVALID_MODEL_JSON` / `INVALID_MODEL_ACTIONS`，上游 HTTP 与超时仍保留原有错误码。保护拒绝不应混写成上游不可达或正式动作准确率。

这些是保守保护，不是完整自然语言理解或条件求值器。未覆盖的语言表达、引号中位置、指令对象关联、条件真实状态与用户授权仍需更完整的语义验证；部分合法否定或条件请求会被要求澄清。显式位置匹配也不能证明模型选对了设备类型或数值。

## 验证

新增 8 项真实回环 HTTP 测试，假上游只替代外部模型，适配器、JSON 校验和白名单使用当前真实代码。先观察猜测位置/额外位置/否定与条件变更的 9 个子用例以 `200 != 422` 失败，再实现保护；提前成功宣称测试也先失败后转绿。

测试覆盖缺房间、上下文不能补房间、额外房间使整批拒绝、显式多房间正常、否定和条件变更拒绝、只读查询、空计划和提前成功宣称。
