# 2026-11-13 演示界面补充修复

## 问题来源

现场录制预演发现网页快捷命令仍展示模型式模糊输入，但当前启动方式为 `--rules-only`，模型端点未配置。无房间温度查询返回了与只读查询不符的“需要调整目标”提示；空白日志区固定显示“等待网关确认”；上一请求回查结束后，新输入没有发送提示。

现场摘录中“客厅灯光亮度=100%”来自未指定百分比的开灯语义，符合当前规则；要演示亮度调整应使用明确百分比。“太暗了”缺少房间和目标值，未生成动作属于预期澄清。`有点冷`与`不透气`需要自然语言模型理解，规则模式不会处理，因而从快捷示例移除。所有传感器值仍为PC/MQTT软件实体仿真。

## 修复

- 快捷命令统一到规则模式已支持的客厅60%灯光、客厅温湿度查询、亮度补槽、客厅窗帘及安全拒绝示例。
- 无房间的温湿度查询改为只询问查询房间，并提供受支持的示例，不产生动作。
- 初始日志说明改为“演示说明”，明确没有待确认请求；空历史提示改为“当前没有待确认请求”。
- 旧请求仍只回查、不自动重发。若回查确认旧请求已结束，页面明确告知当前输入尚未发送，并提示再次点击发送。

## 验证

新增 UI 合同测试，覆盖规则模式快捷命令、初始/空状态文案及旧请求回查提示；新增无房间温度查询测试，确认无动作且设备状态不变。完整V6补充回归：427项通过、258个子测试通过；历史兼容5项通过；前端请求恢复5项通过。测试前后，原设备状态和活动事件SHA-256均未变化。

原答辩PPT和作品方案是11月12日封版，仍记录当时的423项测试。本报告记录11月13日界面修复后增加的4项测试及补充回归结果；不能把旧版PPT描述为已包含本次修改。

## 边界

“打开灯”仍表示打开到100%；明确百分比命令适合演示亮度控制。温湿度数据和设备状态属于PC/MQTT软件仿真。`--rules-only` 不提供“有点冷”或“不透气”的自然语言模型理解，这些快捷项已从页面移除。
