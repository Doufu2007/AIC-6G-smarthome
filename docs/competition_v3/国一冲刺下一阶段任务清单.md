# 国一冲刺：下一阶段任务清单

制定日期：2026-11-11。状态：建议方案，下面新增工作尚未执行。依据第三轮实际证据制定；样本数、时长和判据是工程建议，不是官方国一门槛或功效保证。

官方评分：真实性20、创新10、技术落地30、产业推广20、答辩10、协作10。目标是在现有软件原型上补真实需求、必要性、执行闭环和量化价值。奖项无法保证。

## 提交前优先完成

### P0-1 取得本项目真实需求与自拟任务

当前差距：外部反馈0，主要用户是设计假设。已有公开报告不能代替项目需求方。

- 按便利性先邀请3—5名自愿参与者进行探索；若能接触一位实际使用智能家居或负责集成的人，优先听其具体经历。这个数量不能用于推断市场需求或总体满意率。
- 先问原有方式、最近一次具体困扰、实际影响，再演示。没有经历就如实记录，不要求参与者配合制造痛点。
- 让其自行提出3—5个任务，记录原话、实际过程、成功/失败、是否理解结果。预设演示与自拟任务分开，开发成员不计外部用户。
- 原话公开引用单独取得同意；试用工具已有docs/trial_v2/。默认规则版未接模型，复杂任务会失败；不能把该入口误当完整v3模型试用，接入新入口前需验证隔离与采集接线。
- 产出：需求来源表、任务原文、匿名过程记录、正反反馈、用户提出的可接受等待及未确定字段。
- 完成标准：主方案至少一项核心需求能追到实际来源，说明探索范围；没有真实来源的内容继续标为假设，不虚构客户和采用。

建议文书同学组织采集与整理，你核对技术执行记录；未经授权不联系任何第三方。

### P0-2 补强简单策略的公平对照

当前差距：旧留出joint21/24、固定第二端24/24；新36行证明恢复有用，未证明复杂调度优于简单回退。

三臂：健康感知local-first、健康感知second-first、joint。三臂使用相同模型/提示词/白名单/一次恢复/超时，只改变初选策略。恢复规则不得仅提供给joint。

最小规模提案：先冻结策略、评分、条件、运行顺序和停止规则，再由未参与调参的同学自拟24条新命令并人工固定参考，其中12条复杂可执行、6条需澄清、6条拒绝。新任务若用于开发，则从新测试集中退出；旧20条和H05继续留作历史，不据其调参后追称留出。只有数据隔离成立，才称未用于调优的测试。

12条可执行命令×3臂×6条件=216行；12条澄清/拒绝×3臂×健康条件=36行，合计252行。条件为健康、本地固定700ms代理等待、第二端同样等待、本地POST503、第二端POST503、两端POST503；沿用旧延迟并对称设置，不看结果后放大。它们仍是软件代理机制实验，不是实网故障频率或6G测量。

只有24条不同命令，252行包含重复条件，不能宣称252个独立任务或独立用户。按条件和任务类型分开统计完整动作/状态、澄清/拒绝正确性、越权动作、全请求时延、成功请求时延、POST数、恢复次数和250ms达标。固定初态、配对输入与观测、轮换顺序、区分冷启动与预热；保留错误和全量记录。小样本分位数只作描述，不能据小差异宣称显著优势。

完成标准：能回答joint在什么条件有价值、额外成本是什么、什么情况下简单策略足够。如果简单策略相当或更好，采用简单默认，joint作为资源扩展；不能为维护原方案筛选有利条件。真实用户与平台兼容证据另行取得。

### P0-3 拆解并改进真实时延

当前差距：成功250ms内0/18，最短841.612ms；演示单次约3.37秒。250ms为旧应用配置，既不是官方要求，也没有客户确认。

- 对接收、C决策、健康等待、首端规划、备用规划、输出校验、设备提交、状态确认分别计时；计时边界和并发等待明确。
- 区分“请求收到”“计划生成”“状态已确认”，不能以界面先显示收到证明任务完成。
- 优先测不改变安全含义的改进：减少重复上下文、限制冗余输出、模型常驻、已明确支持的规则快速路径。新增规则不得把模糊任务擅自补成成功，不能为新测试集写答案表。
- 每次只在开发集验证方案选择，最终冻结新版本后才跑独立测试；旧模型、提示词、H05和日志不覆盖。
- 产出：时延分解表、优化前后同输入对照、完成率/失败/调用数、p50/p95及样本数；小样本尾部不当作SLA保证。
- 完成标准：说明主要瓶颈、改善是否以质量或开销为代价、实际未达到的目标。若业务接受秒级完成，必须由真实需求形成有来源的目标修订，保留原250ms未达记录。

### P0-4 统一正式材料并录制当前版本

当前差距：v3是增量报告，v2方案/答辩/佐证及视频尚未统一反映新功能。

- 文书同学用同一主线更新：谁的问题→当前流程→方案→差异→可复核结果→部署/成本→适用边界。
- 建立“主张—指标定义—数值/分母—环境—原始路径—材料页码”索引。真实模型、模拟状态、代理故障、预期目标分层标记。
- 新录3—5分钟实际操作：正常任务、明确来源、合格故障恢复、拒绝/断连、状态确认。若不能全部现场连续演示，录制/剪辑与历史数据来源明确，不能据视频节奏推算时延。
- 方案PDF≤15MB，MP4≤300MB，答辩PDF、合并佐证PDF、匿名要求、300—500字简介、永久链接与提取信息按官方要求检查。
- 完成标准：正式文件均是同一版本，视频展示与代码一致，每个核心数字均可回到原始记录。参赛者最终人工核对和上传另行实际执行。

## 技术继续补强，提交前完成不了则列入决赛前验收

### P1-1 把独立回执合同接入正式执行通道

当前device_receipts只在独立夹具验证，未接生产网关。新增版本应实现：原网关动作校验→持久command_id/请求哈希/待确认记录→设备或平台适配器→回执/状态回查→向操作者报告完成、部分完成或未知。

用SQLite等保存待执行/已提交/已确认/未知状态，绑定可信的设备/服务身份。测试断连、ACK丢失、重复请求、同ID异payload、重启后对账、部分动作执行。超时未知时不自动重发动作。多物理设备没有天然原子回滚，逐项报告已执行/未执行/未知，不承诺物理exactly-once。

产出为新适配器、数据库schema、重启与故障原始记录、网关端到端事件；不能以独立fixture测试数替代已接线证据。软件模拟、实际平台状态与物理ACK分别验收。

### P1-2 补真正的平台或独立节点接入

不建议临近截止盲买开发板/无人机。优先借一套熟悉且获授权的低风险灯具；没有设备时可先接实际Home Assistant实例或MQTT服务的软件实体，用其真实API/事件验证适配。平台软件实体不是物理设备，状态采用乐观更新时也不能证明实物动作。

若同学有可借用电脑，将一个候选迁到独立节点，记录两台资产、模型/运行时哈希、实际链路和资源；无需改用AutoDL，也不把独立LAN/WAN说成6G。没有第二机器时同机结果继续保留同机范围。

完成标准：至少一个真实平台适配或独立部署的端到端过程可复现；若借到实物，再追加命令→ACK→物理状态的证据。

### P1-3 让AI与通信的关系在运行中可追踪

沿用docs/value/ai6g_mapping.md的ITU/ETSI来源。至少记录value/unit/source/observed_at/age/known，WAN/LAN分开，缺队列/显存仍未知。

在同输入与初态下，分别改变仅网络、仅算力、两者共同和观测过期条件，检查C是否按已声明约束排除候选；并将选择、实际模型、动作校验和最终回执用同一trace连起来。优先测到哪些约束真正决定业务完成，避免只展示字段变色。

产出为接口schema、采样记录、策略事件和端到端追踪图。自建观测/平台适配不是MEC认证，当前网络与代理实验不是6G空口；需要运营商平台或试验网的部分保留未来接口与验收计划。

### P1-4 补可复现价值与稳定性

- 让同学按说明从新目录独立启动，记录安装、首次完成任务、定位一次错误、恢复、回滚的实际工时；指导提示也保留。这是开发协作/可用性证据，不能算独立客户采用。
- 在冻结请求率和故障序列下做短时连续运行，再按资源和场景决定是否延长，报告期间请求数、丢失/重复执行、错误、资源峰值、日志增长与恢复。24小时不天然等于生产稳定。
- 记录实际采购/分摊、整机电量积分、电价、安装/维护工时、模型收费，缺项仍unknown。无整机电表就不把GPU板卡功耗当整机节能。
- 与原有操作/简单方案按同任务比较成功完成数、等待、人工重试和部署工时；愿意试用不等于购买，不要求先有收入或专利。
