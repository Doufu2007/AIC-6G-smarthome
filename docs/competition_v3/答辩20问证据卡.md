# SenseHome 答辩20问证据卡

2026年11月11日。短答先说事实，再报证据范围。下列均为备答稿，不是参赛者已完成的现场答辩记录。

| 追问 | 建议短答 | 核验入口与边界 |
|---|---|---|
| 1. 到底为谁解决什么问题？ | 设计面向存量住宅集成服务，让家庭AI入口在候选模型不可靠时仍能完成受支持任务，并明确报告未完成。需求方尚未确认。 | 整改与冲刺路线§2；外部反馈0 |
| 2. 没有6G，为什么参加？ | 赛题允许面向实际需求的设计。已做应用侧网络/算力观测与调度接口；未来承载可替换，当前没有6G空口测量。 | docs/value/中的ITU/ETSI映射；不称6G实测 |
| 3. 为什么不只用规则？ | 明确支持的简单命令走规则，复杂多动作由模型规划；必要目标缺失仍澄清。模型没有绕过动作合同。 | offload_gateway.py；冻结命令与规则测试 |
| 4. 为什么不用Home Assistant或Ollama？ | 它们已有本地意图/模型接入能力。我们提供可替换的观测与C选择、规划恢复、统一动作约束和证据记录；没有同硬件同任务性能胜出证据。 | docs/value/竞品来源与对标；不能称替代所有平台 |
| 5. 为什么不local-first失败后再回退？ | 这是强且合理的基线。当前36行只隔离恢复增量，未证明联合资源策略优于同款简单回退；下一次应同条件比较。 | 整改路线§5；保留固定第二端24/24 |
| 6. cloud真的在云上吗？ | 当前是同机第二逻辑槽位，两个模型共享GPU。独立端云尚未部署。 | runtime_manifest.json中的argv与模型路径 |
| 7. 503是造的吗？ | 是自建代理真实返回的受控HTTP503，上游模型仍健康。验证异常机制，不是自然事故或服务崩溃。 | proxy_records、registration、GET与POST时间 |
| 8. v2和v3测的故障有什么差别？ | v2决策前已知模型503；v3先GET清单成功，再令POST失败，测探测与调用之间的竞态。 | 两版registration与块记录；不可混算 |
| 9. 新恢复到底改善多少？ | 仅本地POST503时原网关0/6、新臂6/6；健康均6/6；两端失败均0/6。每格是两条旧命令三次重复。 | race_v3_portfix/rows与独立复算；非总体可靠性 |
| 10. 恢复后会执行两次吗？ | 包装器只规划，网关执行一次；正式36行与测试检查单请求次数。跨请求幂等由独立设备合同验证，尚未实物接入。 | executor_calls、device_receipts/；不承诺物理exactly-once |
| 11. 10秒预算能保证10秒完成？ | 不能。它只限制发起备用；同步推理与健康各有超时，最终耗时单独记录。 | README_recovery；每行wall_ms |
| 12. 健康、队列、显存真实吗？ | 健康来自实际HTTP并显示缓存年龄；未观测队列/显存是未知。代理准入等待不是GPU排队。 | health_snapshots；dashboard健康字段 |
| 13. 页面怎么证明设备执行了？ | 当前只证明网关报告和PC JSON状态一致。已去掉断连伪成功，不能据页面说物理灯具亮了。 | browser/、device_state、HTML修复 |
| 14. R类命令是不能还是不愿意？ | 当前接口与白名单不支持燃气/安防控制、shell或删文件，没有此执行能力；策略也明确拒绝越权。原始标签已人工确认。 | 冻结20条；白名单和拒绝测试 |
| 15. 有真实用户吗？ | 当前项目外部反馈0。公开问题报告只说明技术背景，自动化浏览与自测均分开计数。 | docs/competition_v2/public_user_reports.json；trial_v2 |
| 16. 准确率到底是多少？ | 不给混合准确率。人工/开发/注入/程序留出/受控故障分别统计；留出joint21/24、第二端24/24。 | sealed_results.md与各注册原始行 |
